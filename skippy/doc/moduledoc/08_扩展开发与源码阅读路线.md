# 扩展开发与源码阅读路线

## 推荐源码阅读路线

按下面顺序读最顺：

1. `skippy/core/model.py`
2. `skippy/core/clustercontext.py`
3. `skippy/core/predicates.py`
4. `skippy/core/priorities.py`
5. `skippy/core/scheduler.py`
6. `skippy/core/storage.py`
7. `sim/skippy.py`
8. `sim/faas/system.py`
9. `examples/03_skippy_scheduler/`

## 为什么按这个顺序

先读 `model.py`，因为所有调度逻辑都围绕 Node、Pod、Container、SchedulingResult 展开。

再读 `clustercontext.py`，因为调度器所有状态读取和写回都通过它完成。

然后读谓词和优先级，理解“过滤”和“打分”。

最后读 `scheduler.py`，就能把整个流程串起来。

`sim/skippy.py` 是 faas-sim 与 Skippy 的桥。理解它之后，才能明白 Skippy 如何真正参与实验。

## 如何自定义谓词

自定义谓词需要继承 `Predicate`：

```python
from skippy.core.predicates import Predicate


class RequireGpuPredicate(Predicate):
    def passes_predicate(self, context, pod, node):
        return "capability.skippy.io/nvidia-gpu" in node.labels
```

然后传给 Scheduler：

```python
scheduler = Scheduler(
    cluster_context,
    predicates=[
        PodFitsResourcesPred(),
        RequireGpuPredicate(),
    ],
)
```

适合写成谓词的逻辑：

- 必须满足的资源约束；
- 必须满足的标签约束；
- 不满足就绝对不能放置的硬件约束；
- 安全隔离约束；
- 节点黑名单/白名单。

## 如何自定义优先级函数

自定义优先级需要继承 `Priority`：

```python
from skippy.core.priorities import Priority


class PreferLargeMemoryNode(Priority):
    def map_node_score(self, context, pod, node):
        return node.allocatable.memory

    def reduce_mapped_score(self, context, pod, nodes, node_scores):
        return _scale_scores(node_scores, context.max_priority)
```

优先级适合表达“偏好”，不是硬约束。

适合写成优先级的逻辑：

- 更靠近用户；
- 更靠近数据；
- 更少镜像拉取；
- 更低成本；
- 更低执行时间预测；
- 更低资源争用；
- 更均衡资源利用。

## 如何调整默认调度策略

最简单方式是改权重：

```python
from skippy.core.scheduler import Scheduler
from skippy.core.priorities import (
    BalancedResourcePriority,
    LatencyAwareImageLocalityPriority,
    DataLocalityPriority,
)

scheduler = Scheduler(
    env.cluster,
    priorities=[
        (1.0, BalancedResourcePriority()),
        (2.0, LatencyAwareImageLocalityPriority()),
        (3.0, DataLocalityPriority()),
    ],
)
```

这样 Skippy 会更重视数据本地性。

## 如何自定义 ClusterContext

如果你不在 faas-sim 中使用 Skippy，可以自己实现 `ClusterContext`。

必须实现：

```python
get_init_image_states()
get_bandwidth_graph()
list_nodes()
get_next_storage_node(node)
```

如果要支持镜像远程查询，还可以覆盖：

```python
retrieve_image_state(image_name)
```

如果要支持不同的数据布局，可以扩展：

```python
get_storage_nodes(urn)
```

## 如何在 faas-sim 中替换 Scheduler

可以继承 `Simulation`，覆盖 `create_scheduler()`：

```python
from sim.faassim import Simulation
from skippy.core.scheduler import Scheduler


class MySimulation(Simulation):
    def create_scheduler(self, env):
        return Scheduler(
            env.cluster,
            priorities=[...],
            predicates=[...],
        )
```

也可以参考：

```text
examples/03_skippy_scheduler/scheduler.py
```

该样例保留默认 Skippy 调度语义，只增加观测指标。

## 调试 Skippy 的建议

调试时优先看：

- Pod 资源请求；
- Pod labels；
- Node labels；
- Node allocatable；
- feasible_nodes 数量；
- 每个优先级函数的分数；
- selected_node；
- needed_images；
- place_pod_on_node 后节点资源是否变化。

如果调度失败，先查：

1. 节点资源是否足够；
2. 是否被 `data.skippy.io/storage` 标签过滤；
3. Pod 的资源请求是否过大；
4. 节点架构是否能找到镜像大小；
5. 存储索引是否包含数据对象；
6. 带宽图是否包含需要的方向。

## 常见误区

误区一：Skippy 会真正拉镜像。

不会。Skippy 只返回 `needed_images`。镜像拉取耗时由 faas-sim 的 Docker 模拟逻辑处理。

误区二：Skippy 会真正执行函数。

不会。函数执行由 `FunctionSimulator` 或 watchdog 处理。

误区三：优先级函数可以过滤节点。

不建议。硬约束应该写成 Predicate，优先级函数只表达偏好。

误区四：`place_pod_on_node()` 表示容器已经启动。

不是。它只表示调度器状态已经写回，容器启动仍在 faas-sim 生命周期里继续模拟。

误区五：数据本地性只看节点是否存储数据。

不完全是。Skippy 会结合对象大小和带宽估算传输时间，数据不在本地时也可能因为带宽高而得分不错。
