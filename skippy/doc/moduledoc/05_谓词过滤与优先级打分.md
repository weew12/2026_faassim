# 谓词过滤与优先级打分

## 谓词 Predicate

谓词用于判断节点是否可行。

接口：

```python
class Predicate:
    def passes_predicate(self, context, pod, node) -> bool:
        ...
```

返回：

- `True`：节点可进入打分；
- `False`：节点被过滤。

## `PodFitsResourcesPred`

该谓词检查资源是否足够。

逻辑：

```text
requested.cpu <= node.allocatable.cpu
requested.memory <= node.allocatable.memory
```

它会累加 Pod 中所有容器的资源请求。

## `CheckNodeLabelPresencePred`

该谓词检查节点标签是否存在。

两种模式：

- `should_be_present=True`：要求标签存在；
- `should_be_present=False`：要求标签不存在。

默认调度器使用：

```python
CheckNodeLabelPresencePred(["data.skippy.io/storage"], False)
```

含义是普通函数不要调度到存储专用节点。

## 优先级 Priority

优先级函数用于给可行节点打分。

接口：

```python
class Priority:
    def map_node_score(self, context, pod, node) -> int:
        ...

    def reduce_mapped_score(self, context, pod, nodes, node_scores) -> List[int]:
        return node_scores
```

`map_node_score()` 是单节点计算。

`reduce_mapped_score()` 是全候选节点归一化。

## `BalancedResourcePriority`

资源均衡优先级。

它关心 CPU 和内存请求比例是否均衡。

简化理解：

```text
cpu_fraction = requested_cpu / allocatable_cpu
mem_fraction = requested_mem / allocatable_mem
score = (1 - abs(cpu_fraction - mem_fraction)) * max_priority
```

如果 CPU 和内存占比越接近，得分越高。

这个策略可以避免某个节点只剩 CPU 或只剩内存，导致后续 Pod 很难放置。

## `LatencyAwareImageLocalityPriority`

带宽感知镜像本地性优先级。

它估算如果 Pod 放到某节点，需要从 registry 拉多少镜像数据，以及拉取要花多长时间。

逻辑：

1. 遍历 Pod 容器；
2. 判断候选节点是否已有镜像；
3. 没有镜像则累加镜像大小；
4. 使用 `registry -> node` 带宽估算传输时间；
5. 传输时间越小，最终分越高。

相比普通镜像本地性，它不仅看“有没有镜像”，还看“拉镜像的链路快不快”。

## `LocalityTypePriority`

位置类型优先级。

它读取节点标签：

```python
node.labels["locality.skippy.io/type"]
```

默认映射：

```python
edge -> 10
cloud -> 0
```

含义是更偏好边缘节点。

## `DataLocalityPriority`

数据本地性优先级。

它关注函数输入数据和输出数据的位置。

常用 Pod 标签：

```text
data.skippy.io/receives-from-storage/path
data.skippy.io/sends-to-storage/path
```

调度器通过 `StorageIndex` 查对象大小和存储节点，然后用带宽估算传输时间。

输入读取：

```text
storage_node -> candidate_node
```

输出写回：

```text
candidate_node -> storage_node
```

传输时间越短，得分越高。

## `CapabilityPriority`

硬件能力匹配优先级。

它使用 `capability.skippy.io/...` 标签表达能力。

例如节点标签：

```python
{
    "capability.skippy.io/nvidia-gpu": "",
    "capability.skippy.io/nvidia-cuda": "10",
}
```

Pod 如果也声明相同标签和值，就算匹配。

匹配数量越多，原始分越高，再缩放到统一评分范围。

## 如何调整调度倾向

最常见方式是改优先级权重：

```python
Scheduler(
    cluster_context,
    priorities=[
        (2.0, BalancedResourcePriority()),
        (1.0, LatencyAwareImageLocalityPriority()),
        (0.5, LocalityTypePriority()),
        (3.0, DataLocalityPriority()),
        (1.0, CapabilityPriority()),
    ],
)
```

权重越大，该因素对最终节点选择影响越大。
