# 调度主流程：过滤、打分、绑定

Skippy 的主流程在 `skippy/core/scheduler.py` 的 `Scheduler.schedule()` 中。

## 总流程

```text
schedule(pod)
  |
  |-- list_nodes()
  |
  |-- passes_predicates(pod, node)
  |
  |-- priority.map_node_score(...)
  |
  |-- priority.reduce_mapped_score(...)
  |
  |-- sum(weight * score)
  |
  |-- max(score)
  |
  |-- needed_images
  |
  |-- place_pod_on_node()
  |
  └-- SchedulingResult
```

## 第一步：获取节点

调度器首先调用：

```python
nodes = self.cluster_context.list_nodes()
```

在 faas-sim 中，`SimulationClusterContext.list_nodes()` 会把 Ether 节点转换成 Skippy 节点，并排除 Docker registry 节点。

## 第二步：计算需要多少可行节点

Skippy 保留 Kubernetes 的大规模调度思想：不一定总是给所有节点打分。

相关参数：

- `min_feasible_nodes_to_find = 100`
- `min_feasible_nodes_percentage_to_find = 5`
- `default_percentage_of_nodes_to_score = 50`
- `percentage_of_nodes_to_score`

如果集群很小或配置为 100%，就扫描全部节点。

如果集群很大，可以只找一部分可行节点参与打分，降低调度开销。

## 第三步：谓词过滤

调度器从 `last_scored_node_index` 开始扫描节点：

```python
filtered = filter(
    lambda node: self.passes_predicates(pod, node),
    islice(cycle(nodes), start, start + len(nodes))
)
```

这样做的原因是避免每次调度都从第一个节点开始，降低固定顺序带来的偏置。

谓词过滤要求：

```python
all(predicate.passes_predicate(context, pod, node)
    for predicate in self.predicates)
```

只有通过所有谓词的节点才进入打分阶段。

## 第四步：优先级打分

优先级函数是两阶段模型：

```python
mapped_nodes = [
    priority.map_node_score(cluster, pod, node)
    for node in feasible_nodes
]

reduced_node_scores = priority.reduce_mapped_score(
    cluster, pod, feasible_nodes, mapped_nodes
)
```

`map_node_score()` 计算单个节点的原始分数或代价。

`reduce_mapped_score()` 在所有候选节点之间做归一化或反向缩放。

例如：

- 资源均衡分本身就是 0 到 10；
- 数据传输时间是越小越好，所以要反向缩放；
- 能力匹配数量要缩放到统一分数范围。

## 第五步：加权求和

每个优先级函数有权重：

```python
default_priorities = [
    (1.0, BalancedResourcePriority()),
    (1.0, LatencyAwareImageLocalityPriority()),
    (1.0, LocalityTypePriority()),
    (1.0, DataLocalityPriority()),
    (1.0, CapabilityPriority()),
]
```

总分计算方式是：

```text
total_score(node) =
  weight_1 * priority_1(node)
  + weight_2 * priority_2(node)
  + ...
```

最后选总分最高节点。

## 第六步：计算缺失镜像

选中节点后，调度器会检查该节点是否已经缓存 Pod 需要的镜像：

```python
if normalize_image_name(container.image) not in host_images:
    needed_images.append(normalize_image_name(container.image))
```

`needed_images` 会放入 `SchedulingResult`，供 faas-sim 后续模拟镜像拉取。

## 第七步：写回集群上下文

如果选中了节点，调度器调用：

```python
self.cluster_context.place_pod_on_node(pod, suggested_host)
```

这个动作非常重要，它会改变后续调度看到的状态：

- 节点剩余 CPU 减少；
- 节点剩余内存减少；
- Pod 被加入节点；
- 镜像被登记到节点镜像缓存；
- 镜像分布节点数可能增加。

所以 Skippy 是在线调度器。前一个 Pod 的放置会影响后一个 Pod 的选择。

## 没有可行节点时会怎样

如果没有可行节点：

```python
suggested_host = None
needed_images = None
```

faas-sim 的 `DefaultFaasSystem.run_scheduler_worker()` 会发现 `result.suggested_host` 为空，然后：

- 从副本列表移除当前副本；
- 如果还有候选服务/镜像，则尝试下一个；
- 如果没有候选项，则记录调度失败。
