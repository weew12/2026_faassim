## 2. ether 总体架构

ether 把"网络仿真"拆成 **4 层核心 + 6 类辅助**:

```
┌────────────────────────────────────────────────────┐
│  Layer 1 · 核心类型与仿真引擎    core.py  (537 行)  │
│     Node / Capacity / Link / Connection            │
│     Route / Flow / UninterruptingFlow              │
│     + add_and_rebalance / rebalance (公平共享)     │
├────────────────────────────────────────────────────┤
│  Layer 2 · 组合式拓扑单元 DSL    cell.py  (372 行)  │
│     UpDownLink / Cell / Host / LANCell             │
│     SharedLinkCell / GeoCell                       │
├────────────────────────────────────────────────────┤
│  Layer 3 · DiGraph + 路由缓存    topology.py(196 行)│
│     Topology(nx.DiGraph) + 路由缓存 + 两种 RTT     │
├────────────────────────────────────────────────────┤
│  Layer 4 · Vivaldi 网络坐标      vivaldi.py(122 行) │
│     VivaldiCoordinate + execute                    │
├────────────────────────────────────────────────────┤
│  工具层                                              │
│     util.py / export.py / vis.py                   │
├────────────────────────────────────────────────────┤
│  子包层                                              │
│     blocks/        预置设备/回传/Cloudlet 工厂       │
│     scenarios/     三个真实研究场景                  │
│     qos/           4 个链路时延分布                  │
│     inet/          真实云区域延迟图(graphml)         │
│     cli/           命令行工具                       │
│     converter/     外部格式转换(PyVis 等)           │
└────────────────────────────────────────────────────┘
```

**关键设计原则**(贯穿整个 ether):

- `NetworkNode = Union[Node, Link, TransparentLink]` —— 拓扑图顶点的统一类型
- **Node→Node 不能直连**,必须经过 Link 或 TransparentLink(字符串)
- `Connection` 支持固定时延或随机分布两种模式
- `Route.rtt` 是**双向**(RTT),`latency` 是单向(RTT/2)
- 公平共享带宽算法 `rebalance` 走 max-min fairness + SimPy `Interrupt` 中断驱动
- 路由缓存用**众数**(稳定),使用时再**采样**(抖动)

## 5. 与 faas-sim 的对接

faas-sim 中的下列模块通过 ether 完成网络仿真:

| faas-sim 模块 | 用到 ether 的什么 |
|---|---|
| `sim/topology.py` | Topology、Node、Link、Connection |
| `sim/net.py` | Flow、rebalance、TCP 握手 1.5×RTT |
| `sim/docker.py` | Image pull = Flow(节点间数据传输) |
| `sim/faas/*` | Node.arch / Node.labels 做调度约束 |
| `ext/raith21/*` | 复用 blocks/ 的预置设备 + qos 分布 |

## 7. ether 之于 faas-sim 的定位

ether 在 faas-sim 整体架构中的角色:

```
┌────────────────────────────────────────────────────┐
│  Application Simulation                            │
│  ├─ FaaS 调度器 (sim/faas/*)                       │
│  ├─ Docker 镜像管理 (sim/docker.py)                │
│  └─ 工作负载生成 (sim/workload/*)                  │
├────────────────────────────────────────────────────┤
│  Network Simulation  ←【ether 在这一层】            │
│  ├─ 拓扑构建 (Topology / Cell)                     │
│  ├─ 节点/链路建模 (Node / Link / Connection)       │
│  ├─ 流量传输 (Flow / UninterruptingFlow)           │
│  └─ 路由与 RTT (topology.route / Vivaldi)          │
├────────────────────────────────────────────────────┤
│  Discrete Event Simulation                         │
│  └─ SimPy 协程(ether 用 simpy 推进 Flow)           │
└────────────────────────────────────────────────────┘
```
